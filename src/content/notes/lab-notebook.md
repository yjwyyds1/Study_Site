## 先写现象，再写解释

我希望看到 `starts with INFO: true`，在判断前缀时实际看到 `false`。只记录“输出错误”不够：另一位读者需要知道输入是什么、如何构建、在哪一行停下来。

| 要留的证据 | 这个场景的例子 |
| --- | --- |
| 最小输入 | `INFO service ready` |
| 预期和实际 | 预期 true，错误版为 false |
| 独立验证 | 断点停在赋值前，单步执行后检查 `is_info` |
| 根因 | 匹配串意外写成了 `WARN `；代码语法和类型检查仍可通过 |
| 修复与回归 | 恢复 `INFO `；再用 `INFORMATION ready` 验证不误认 |

## 记下下一次实验

把同一流程用于自己的 LogScan：挑一个能通过编译却产生错误结果的输入，把一次错误定位过程写成两三段。区分“看见什么”和“根据什么推断”。如果第二天无法重现，补齐缺失的构建命令、样本或工具版本。
