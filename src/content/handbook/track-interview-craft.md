## 本篇总览（TRK-43 ~ TRK-50）

学完一门语言和一堆底层课后，从“能写代码的学生”进化到“值得托付生产系统的工程师”，还差最后 8 项职业内功：**会审代码、敢查线上崩溃、会写设计文档、能做诚实基准测试、读得懂工业开源仓库、能在面试里把底层讲到无懈可击**。本篇打通收官 `TRK-43` ~ `TRK-50`。

## 一、工业级 Code Review（代码评审）六维核对单（TRK-43）

不要只盯着花括号放哪一行或变量名格式（这些统统交给 `clang-format` / CI），审任何一段工业 C++ 代码只盯六条命门：
1. **所有权与生命周期**：裸指针/引用/`string_view`/`span` 是否明确谁负责销毁？跨异步回调或线程边界时，对象会先死吗？
2. **异常与错误路径**：文件打不开、磁盘满、`malloc`/解析失败、网络半帧截断时，资源会漏吗？退出码和状态会污染吗？
3. **边界与整数安全**：下标越界、`size_t` 减法下溢、协议长度恶意超大 `4 + len` 溢出、`std::move` 后再次使用？
4. **并发与锁粒度**：有没有持锁调用阻塞 I/O 或未知回调？有没有两处加锁顺序相反埋死锁？条件变量是不是用了 `if` 而非 `while`？
5. **无界资源隐患**：有没有没设上限的 `std::vector` / `queue` / 连接表被异常输入撑爆 OOM？
6. **可测性与变更最小化**：是否附带了覆盖失败分支的单元测试？改动有没有牵扯无关文件？

## 二、线上生产崩溃 Post-mortem（验尸排查）标准流程（TRK-44）

凌晨三点服务器突然 Core Dump 或 CPU 100%，按四步冷静取证，绝不盲目重启毁灭现场：
1. **保现场**：第一时间保存 `coredump` 文件、当时完整日志尾巴（`journalctl`）、运行配置和监控截图；如果只是假死 CPU 100%，先用 **`gcore <PID>`** 或 **`perf record -p <PID> -g -- sleep 10`** 录下活体调用栈再重启！
2. **定位指令与源码**：用对应版本带完整符号表（`RelWithDebInfo` / 分离 `.debug` 文件）执行 `gdb ./app core`，运行 `bt` 和 `thread apply all bt` 锁定崩溃线程与所有等待线程。
3. **构造最小离线复现 + Sanitizer**：把触发崩溃的那 1 条网络包或日志样本剥离成 30 行测试输入，在本地打开 `-fsanitize=address,undefined`（或 `thread`）复跑一遍抓出第一现场根因。
4. **写无责复盘文档（Blameless Post-mortem）**：记录“时间线 → 直接根因 → 为什么测试/监控漏过了 → 永久修复 + 回归测试防线”，对事不对人！

## 三、编写架构决策记录（ADR）与技术设计文档（TRK-45）

写大改动前先花 2 小时写 1 页设计文档（**ADR, Architecture Decision Record**），比写完 3000 行代码被评审推翻重来省 10 倍时间。一份好 ADR 必须诚实写清 5 块：
1. **背景与约束**：当前遇到了什么问题？性能、兼容、交付截止期硬约束是什么？
2. **备选方案对比（至少 2 个！）**：比如“用 SQLite WAL vs 自研追加日志”，列出各自优缺点与工作量；
3. **最终选择与理由**：为什么当前选方案 A；
4. **不做什么（Non-goals）**：明确划清本次边界防止需求蔓延；
5. **风险、回滚与可观测指标**：上线出问题怎么秒级回滚？看哪几个指标判断成功？

## 四、干净的微基准测试：躲开“骗自己的假快”陷阱（TRK-46）

初学者写 Microbenchmark 十次有九次测出完全荒谬的结果，最常见的三大假快错觉：
1. **死代码消除（DCE）**：循环里算了一百万次没用到返回值，`-O2` 直接整段删空算出 **0 ns**！——必须用 `benchmark::DoNotOptimize(res)` 或 `volatile` 汇总输出校验。
2. **常量折叠**：输入写死编译期常量数组，编译器在编译阶段就算出答案塞进 `mov eax, 42`！——输入应运行时生成或来自不可预测状态。
3. **只测 1 次冷跑 / 忽视分配抖动**：首次运行缺页异常+指令缓存未热，且均值会被某一次 OS 调度毛刺拉歪——永远做 **热身（Warmup） + 多轮统计中位数与 P99**！

## 五、开源 C++ 宝藏源码导读地图（TRK-47）

想真正提高代码审美和工程架构能力，不要只啃语法书，挑下面 4 个工业级高质量 C++ 仓库按模块精读：

| 开源项目 | 体量与阅读难度 | 最值得偷师的精华设计 |
| --- | --- | --- |
| **`fmtlib/fmt`** | 中等（极干净现代 C++20） | 编译期格式串校验 `consteval`、零冗余模板膨胀技巧（类型擦除） |
| **`gabime/spdlog`** | 较小、易读 | 双缓冲异步日志队列、多 Sink 架构、避免锁竞争的工厂注册 |

## 六、高频底层面试“不靠猜”标准讲法（TRK-48）

面试官最讨厌背标准答案却答不出边界条件。对照检验这 5 个必考底层话题：
1. **讲 `std::vector`**：不要只说“动态数组 2 倍扩容”。讲清 `sizeof=24` 三根指针、为什么等比扩容均摊 $\mathcal{O}(1)$（vs 等差扩容退化）、`push_back` 触发扩容使所有迭代器与引用全部失效、`emplace_back` 原地构造与 `noexcept` 移动构造才触发移动而非拷贝！
2. **讲 `std::shared_ptr`**：讲清两块内存/联合控制块（`make_shared` 合并 1 次分配及 `weak_ptr` 延迟释放整块内存的微妙代价）、**引用计数增减本身是原子线程安全，但读写所指对象本体与并发改同一个 `shared_ptr` 仍不安全**、以及 `weak_ptr` 破除环形引用与 `.lock()` 原子判活！
3. **讲 `epoll`**：讲清为什么它比 `select/poll` 快（红黑树长驻内核免重复拷贝 + 就绪回调函数填 `rdllist` 只返活跃连接），以及 ET 模式下为何必须设 `O_NONBLOCK` 循环读到 `EAGAIN`。
4. **讲 B+ 树索引**：讲清为什么数据库选 B+ 树不选红黑树/哈希（矮胖降低磁盘寻道 I/O 次数 + 叶子双向链表极速范围扫描 `BETWEEN`）、聚簇索引 vs 回表 vs 联合索引最左前缀。
5. **讲内存序与 CAS**：讲清 Store Buffer / Invalidation Queue 导致乱序根源、`acquire/release` 配对建立 happens-before 同步消息传递、以及无锁栈 CAS 循环与 ABA 问题。

## 七、系统设计面试实战演练（TRK-49）

面对“设计一个支持千万日志上报的分布式日志收集与检索系统”（正好是 `LogScan` 的放大版！），严格按 4 步节奏沟通，绝不一上来堆组件名：
1. **明确需求与数字估算（5 分钟）**：写入 QPS 多少？每条 500B 计算带宽、每天存多少 TB、保留 7 天需多少盘？容忍秒级还是分钟级延迟？
2. **画端到端主链路（10 分钟）**：`Agent(断点续传+本地限流环形缓冲) → L4/L7 网关 → Kafka 削峰填谷 → 无状态消费清洗 → 列存/ClickHouse 或 ES 索引查询`。
3. **专攻 2 个核心难点深挖（15 分钟）**：
   - **突发流量洪峰怎么保Agent和后端不炸**？（磁盘缓冲限制上限 + 背压限流 + 批提交写入）
   - **网络重传怎么保证统计不多不少**？（客户端 `batch_id` + 存储侧幂等写入 / `LogScan` 唯一约束逻辑）
4. **瓶颈与高可用降级（5 分钟）**：单点容灾、冷热分层转存对象存储 S3、监控与告警阈值。

## 九、微练习与自检

1. 下面这段代码在 Code Review 里至少藏着 3 个严重工程隐患，请全部指出来：
   ```cpp
   void handle_client(int fd) {
       std::string* msg = new std::string(read_packet(fd));
       std::thread([&]() { db_insert(*msg); delete msg; }).detach();
   }
   ```
2. 某同学测 `for (int i = 0; i < 1000000; ++i) sum += i;` 发现开启 `-O2` 后耗时 0 ns 于是得出“百万次加法零耗时”，哪里错了？

<details>
<summary>核对答案</summary>

1. ① Lambda 按引用 `[&]` 捕获局部变量 `msg` 后立即 `.detach()`，`handle_client` 返回后 `msg` 指针变量本身被销毁，子线程解引用悬垂引用直接 UB 崩溃；② `detach()` 后无优雅停机控制，主程序退出或连接暴增时线程无限爆炸；③ 若 `read_packet` 抛异常或 `db_insert` 抛异常会导致内存泄漏且没有先用 `UniqueFd` 托管 `fd`（且手写 `new/delete` 应改为 `std::make_unique` 按值 move 进有界队列由线程池消费）。
2. `-O2` 对常量区间循环直接**编译期数学公式求和折叠 + 死代码消除**（若 `sum` 没输出到外部可观察副作用里甚至直接被整个删光）。合格测试需用外部动态输入并通过 `DoNotOptimize` / 打印校验结果阻止优化消除。

</details>
