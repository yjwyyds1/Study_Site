# C++ 研习手册：后续建设顺序

[完整分级大纲](course-outline.md) · [阶段工时与学习方法](course-method.md)

这条路线优先练独立开发与排错。已发布的项目从单文件 LogScan v0 到多文件 v0.1；算法整块放到项目交付之后按需补修，不作为早期项目的门槛。

## 现在可学：能独立写和拆一个小工程

| 顺序 | 已发布章节 | 动手任务 | 完成证据 |
| --- | --- | --- | --- |
| 1 | [从空白写一个小程序](../src/content/handbook/blank-program.md) | 写一个读输入、分类、计数的程序。练循环、条件、函数、返回值，以及空输入。 | 能从终端重建运行，解释数据怎么从输入走到输出。 |
| 2 | [命令行与版本控制](../src/content/handbook/command-line-git.md) | 复现 IDE 中的构建；在独立练习仓库记录一处行为变化。 | 能用 `git diff` 指出改动，用运行结果证明改动效果。 |
| 3 | [用 CMake 拆分小项目](../src/content/handbook/cmake-targets.md) | 把 LogScan v0 分成解析模块和命令行入口。在 CLion 与终端确认构建的是哪个目标。 | 从干净构建目录生成可执行文件，能区别头文件问题与缺少链接目标。 |
| 4 | [写测试和定位错误](../src/content/handbook/cli-testing.md) | 把单文件实验的测试输入沿用到拆分版；覆盖正常、空输入、坏行和缺失文件。故意改坏一条分类规则，再通过测试和断点定位。 | 检查标准输出、标准错误与退出码；能展示一次“测试失败 → 定位 → 修复 → 再通过”。 |

**交付物：[LogScan v0.1 实验](../src/content/labs/logscan-build.md)**。功能与 v0 相同，实验给出构建命令、验收方法和可下载的参考工程。它是通往 v1 的小步，可以在学完完整的容器或质量模块之前动手。起步优先用你已经接触过的 CLion，GDB 命令行和 Linux 诊断放到后面。

若时间有限，先做 CMake 拆分和一条 CLI 回归测试。若还不能独立写出几十行程序，先完成表中的第 1 项和 v0 小实验，再拆分项目。能不看参考实现改对一个新需求，并解释失败原因，就可以快进。

## 后续各批

| 建设顺序 | 先补的内容 | 项目增量 | 放行条件 |
| --- | --- | --- | --- |
| A · 已发布 | 小程序、Git、CMake、CLI 测试与排错 | **v0.1**：拆开解析与命令行入口 | 干净构建、原有行为通过测试，能用断点解释一次修复。 |
| B · 下一批 | 多文件输入和错误处理，实用 STL、接口设计、构建配置与 CI | **v1**：多文件聚合与确定顺序的输出 | 能分别处理空文件、坏行和缺失文件；在干净环境跑通构建与测试。 |
| C · 求职作品 | Linux 文件与进程诊断、机器层实验、SQLite、交付文档与评审 | **v2**：可查询的本地归档 | 自动导入和查询；对照有无索引的查询计划；复现一次写入失败并验证回滚。能用 README 和排错记录讲清自己做过什么。 |
| 按需补修 | 数据结构、复杂度、排序、树图、DP | **可选扩展**：为日志报告增加 Top-K 或做面试题 | 用简单参考实现校验结果；可以整段跳过，继续项目主线。 |
| D · 系统主线 | 同步与有界队列、TCP 分帧、存储恢复、性能基准 | **v3**：有界日志服务 | 测试读到半条消息、队列满、超时和退出；固定负载记录吞吐、尾延迟和资源用量。 |
| E · 岗位方向 | 按作品和偏好选 Linux 服务端、基础设施／性能、Qt 或嵌入式之一 | **方向作品**：复用已有输入格式与测试 | Qt 可从 v1 分支，嵌入式额外完成机器层实验；服务端与性能方向从 v3 延伸。提交方向特有的边界用例。 |
| F · 深入专题 | 由项目中遇到的问题选择无锁、编译器、存储引擎等主题 | **对照实验或原型** | 留下假设、固定环境、原始结果和结论边界，别人能重跑。 |

同一个阶段内可以按练习暴露的缺口调整章节先后。每周 10–14 小时只是学习试排：先根据一次独立完成构建、调试和记录所花的时间校准。课程撰写按上表分批交付，学习时间和正文发布不是同一份排期。

## 章节发布标准

1. **说明用途和先修。** 以一个实际问题开场，并给出你需要掌握的操作或判断。
2. **提供可跑的例子。** 明确 C++ 标准、环境、构建命令与预期结果。发布前在标注的环境跑一遍；平台差异和尚未跑过的组合单独说明。
3. **有失败证据和练习。** 至少有一个容易出错的对照和一道需要实际修改的练习。提示和参考答案折叠。
4. **有验收和关联。** 给出具体输入、预期、验证命令或解释题，连接到对应项目；验收没过可以留下卡点，回补对应小节。
5. **验证站内可用。** 正文可读后才在知识地图标为已发布；检查目录、搜索、代码和练习记录入口。现有章节地址保持稳定，已有进度继续使用。
