# 计算机网络与服务协议（NET）

[课程总览](../course-outline.md) · [默认路线](route.md) · [实验与验收](logscan.md)

面向 C++20 和 Linux（含 WSL2），先做回环实验，再把协议和连接管理接进 LogScan。以下练习给出预期或判定条件，实测由学习者记录环境、命令、输出和差异。[已有验证记录](../example-verification.md)未覆盖本大纲的 Linux 网络实验。抓包限于自建回环流量。

项目顺序为 [v0 单文件统计](../../src/content/labs/logscan.md) → [v0.1 多文件工程](../../src/content/labs/logscan-build.md) → v1 多文件聚合计划 → v2 本地可查询归档计划 → v3 有界 TCP 服务计划。旧题名 v2 的[服务指导页](../../src/content/labs/logscan-service.md)供 v3 参考，仓库提供分帧与队列单项源码，集成工程和验收仍属计划。

## 第一篇 从地址到传输


### 用观测理解协议栈

- 入口：能在 Linux 终端执行命令并保存输出。
- 能力：定位地址、路由、名字解析和传输层端点。
- 检验：提交一张从域名到应用数据的链路图，附路由、解析和回环抓包证据。

<a id="net-06"></a>

#### NET-06 长度前缀与增量分帧

- 先修：[NET-05](#net-05)、[CPP-09](cpp.md#cpp-09)、[MACH-04](machine.md#mach-04)
- 层级：核心应用（主线）
- 状态：部分覆盖，[TCP 正文](../../src/content/handbook/network-tcp.md)有长度上限演示，[分帧源码](../../public/examples/network-framing.cpp)只演示内存拆分与拼接，协议边界断言待编写。
- 问题：收到半个长度头或连着两条消息时怎么消费缓冲区？
- 小节
  1. 约定 4 字节大端头和字节长度
  2. 区分需更多数据、解出帧和非法长度
  3. 定义空帧与 64 KiB 上限，检查长度后再计算边界
- 能力：能按帧消费字节、保留残片，并在只有超限长度头时拒绝。
- 练习与预期：复用 INFO ready 与 ERROR timeout，7 字节首段预期零帧，补齐后顺序得到两帧且余额为零；再在练习副本添加长度检查，枚举切点并断言教学上限 65536 可解、65537 只给头即拒绝。E3 的服务上限改为 4096 时，用同样办法重测 4096／4097。
- 项目或独立实验：v3 分帧组件，先用内存测试锁定切分与合并。

#### NET-07 截止时间、半关闭与断连

- 先修：[NET-06](#net-06)
- 层级：核心应用（主线）
- 状态：部分覆盖，[TCP 正文](../../src/content/handbook/network-tcp.md)展示 EOF 分支，超时、截断和半关闭策略待编写。
- 问题：只收到半帧就 EOF，或者对端一直慢速送字节，何时终止？
- 小节
  1. 用单调时钟区分空闲超时和整帧截止时间
  2. 用 poll 等待并重新计算剩余预算

- 能力：能实现可诊断的退出路径，并保留半关闭后的响应机会。
- 练习与预期：分别发送完整帧后关闭写端、发送不足一帧后关闭写端、粗粒度慢送超过截止时间，预期得到正常 EOF、截断、超时三类结果。
- 项目或独立实验：v3 慢客户端及断连回归。
