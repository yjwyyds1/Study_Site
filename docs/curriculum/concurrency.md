# 并发与性能（CON）

[课程总览](../course-outline.md) · [默认路线](route.md) · [实验与验收](logscan.md)

以 C++20 和 Linux（含 WSL2）为实验环境。线程实验用支持线程的工具链，Linux 单文件构建加 `-pthread`，CMake 工程使用 `Threads::Threads`。练习列出预期与核对法，实测保留环境、命令、原始输出和差异。[已有验证记录](../example-verification.md)未覆盖本大纲的并发与性能实验。

主线从 [v0 单文件统计](../../src/content/labs/logscan.md) 和 [v0.1 多文件工程](../../src/content/labs/logscan-build.md) 起步，经过 v1 多文件聚合计划与 v2 本地可查询归档计划，进入 v3 有界 TCP 服务计划。旧题名 v2 的[服务指导页](../../src/content/labs/logscan-service.md)提供 v3 集成思路，仓库提供分帧与队列单项源码，完整服务与性能基线属于计划。

## 第一篇 线程与共享状态


### 生命周期与互斥

- 入口：会写函数并能解释对象与资源的作用域。
- 能力：选择线程间的数据传递方式，明确共享状态的保护范围。
- 检验：提交局部统计、互斥统计与参考结果的对照，以及线程退出顺序。

## 第二篇 有界流水线与退出


### 等待、容量与过载

- 入口：能用一把锁保护共享不变量，知道线程如何退出。
- 能力：实现谓词等待、有界交接、明确的关闭与拒绝策略。
- 检验：在容量 1 或 2 下自动核对空等、满等、关闭和多工作线程的记录集合。


<a id="con-04"></a>

#### CON-04 条件变量与谓词等待

- 先修：[CON-03](#con-03)
- 层级：核心应用（主线）
- 状态：部分覆盖，[并发队列正文](../../src/content/handbook/concurrency-queue.md)讲解谓词与虚假唤醒，受控交错和截止时间待编写。
- 问题：通知先于等待到来，消费者如何避免错过已就绪的数据？
- 小节
  1. 用同一把锁修改与检查谓词
  2. 追踪 wait 的解锁、等待和重加锁
  3. 比较 notify_one、notify_all 与按截止时间等待
- 能力：能写出醒后重查状态的等待协议。
- 练习与预期：用一次性同步门 `std::latch(1)` 控制复现顺序。先写后等时生产者在解锁后打开门，消费者过门再检查谓词；先等后写时消费者持锁打开门再进入谓词等待，生产者过门后取得相同的锁。另做一次只通知、不改变状态的对照，将「任务取出」记录与通知次数分开。预期真正写入后各取出一条，空通知不产生任务。
- 项目或独立实验：独立实验，记录谓词与通知事件，超时仅作为测试看门狗。
