## 第一篇 从终端到多文件工程

### 构建、版本与目标

- 入口：能启动终端并进入独立练习目录。

#### ENG-01 终端、路径与进程输入输出

- 先修：零起点
- 层级：入门（起步主线）
- 状态：部分覆盖，[命令行与 Git](../../src/content/handbook/command-line-git.md)覆盖 PowerShell；Bash 与权限待编写。
- 问题：为何 IDE 打得开文件，终端启动却打不开？
- 小节
  1. 当前目录、绝对和相对路径，用存在性检查验证解析位置。
  2. 参数边界、空格和引号，区分 Bash 与 PowerShell 的写法。
  3. 标准流、退出码和 Linux 文件权限，记录失败命令的上下文。
- 能力：能解释工作目录与源码目录的区别，实现一条可复跑的命令。
- 练习与结果：将 sample.log 保存到带空格的练习目录；先在这里运行 `Get-Content -LiteralPath './sample.log'` 或 `cat './sample.log'`，再到父目录重跑，确认相同相对路径找不到文件。改用绝对路径恢复。
- 项目／独立实验：复用 [sample.log](../../public/examples/sample.log)，到 E0 后再重复实验，保存正常文本（stdout）、错误诊断（stderr）与退出状态。

#### ENG-02 预处理、编译与链接

- 练习与结果：给 [hello-minimal.cpp](../../public/examples/hello-minimal.cpp) 加调用和声明，预期 -c 成功、链接非零；补定义后输出 LogScan ready。

#### ENG-03 Git 工作区、暂存与评审

- 先修：[ENG-01](#eng-01)
- 层级：入门（起步主线）
- 状态：部分覆盖，[命令行与 Git](../../src/content/handbook/command-line-git.md)已有暂存实验；分支评审与二分待编写。
- 问题：保存文件之后，下一份提交究竟会包含哪些改动？
- 小节
  1. 分开比较工作区、索引与 HEAD，检查忽略规则。
  2. 在练习仓库用分支和小提交记录可复核的行为变化。
  3. 写可重复的通过／失败判据，用 bisect 定位引入回归的提交。
- 能力：能解释两种 diff 的基准，用变更和测试结果支撑评审。
- 练习与结果：对 [classify.cpp](../../public/examples/classify.cpp) 在独立仓库先提交原样文件，把 OTHER 改成 UNKNOWN 并暂存，再改成 FALLBACK；用 `git diff --cached` 对照，预期状态为 MM，暂存差异仍是 OTHER → UNKNOWN。
- 项目／独立实验：在隔离仓库制造一次已知回归，用分类器输入作为判据，记录二分命中的提交。

#### ENG-06 断点、调用栈与 Linux 调试

- 先修：[ENG-05](#eng-05)
- 层级：核心应用（项目主线）
- 状态：部分覆盖，[CLion 断点](../../src/content/handbook/toolchain.md)、[测试排错](../../src/content/handbook/cli-testing.md)及 [GDB 起步](../../src/content/handbook/linux-process-io.md)已有；完整诊断流程待编写。
- 问题：程序读到了 ERROR:，为什么却增加了 ERROR？
- 小节
  1. 固定可执行文件、参数、输入、工作目录和带符号的 Debug 构建。
  2. 用断点、单步、局部变量与调用栈区分分词和比较。
  3. 在 GDB 中复现同一错误，区分逻辑失败、信号退出和缺调试符号。
- 能力：能根据最小复现选断点并用现场证据验证假设。
- 练习与结果：把精确匹配改成前缀匹配，预期 token 保留冒号，错误分支把 error 从 0 加到 1；恢复后仅 unknown 增加。
- 项目／独立实验：用 v0.1 核心重做一次定位，分别保存失败测试与 GDB 栈帧记录。
