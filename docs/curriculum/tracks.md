# 岗位方向

[课程总览](../course-outline.md) · [默认路线](route.md) · [实验与验收](logscan.md)

选一条方向完成专题与作品验收。服务端和性能方向延伸 v3，Qt 和嵌入式从 v1 分支。每条路线提交构建说明、固定输入、原始输出和至少一个失败用例。

[项目链](../course-method.md)已有 [v0 单文件统计](../../src/content/labs/logscan.md)和 [v0.1 多文件工程](../../src/content/labs/logscan-build.md)，后续为 v1 多文件聚合计划、v2 本地归档计划、v3 TCP 服务计划。[旧题名为 v2 的服务指导页](../../src/content/labs/logscan-service.md)可借用流水线和测试思路，服务相关单项源码只有[分帧](../../public/examples/network-framing.cpp)和[队列](../../public/examples/concurrency-queue.cpp)。

[既有验证记录](../example-verification.md)中的 v0、v0.1 结果来自 Windows。以下方向项目及其 Linux、Qt、目标板或模拟器结果均待执行。验收时记录版本、环境、负载、预期与实际结果，响应时间和资源占用以实测为准。

#### TRK-01 事件循环、连接状态与截止时间

- 先修：[OS-01](os.md#os-01)、[CPP-10](cpp.md#cpp-10)
- 层级：核心应用（方向选修）
- 状态：部分覆盖，[TCP 分帧](../../src/content/handbook/network-tcp.md)覆盖字节流与分帧，事件循环和连接管理待编写。
- 问题：慢客户端只发半条消息时，如何持续服务其他连接？
- 小节
  1. 非阻塞描述符与 epoll 就绪通知
  2. 连接的输入输出缓冲、部分读写与回收

- 项目或独立实验：为 v3 写两客户端集成测例，复用分帧源码并核对缓冲上限。

#### TRK-02 过载策略、运行指标与部署

- 先修：[TRK-01](#trk-01)、[ENG-04](engineering.md#eng-04)

- 项目或独立实验：给 v3 提交部署配置和本机过载脚本，保留超时与拒绝的原始日志。

#### TRK-03 有序退出、重启与版本回滚

- 先修：[TRK-02](#trk-02)
- 层级：核心应用（方向项目）
- 状态：待编写，[旧服务指导页](../../src/content/labs/logscan-service.md)提供队列排空测试建议。
- 问题：服务收到停止信号时，已经确认的批次还能找回吗？
- 小节
  1. 停止新接入、排空或按截止时间结束，记录未确认任务
  2. 重启后对账及未确认重试去重
  3. 发布与回滚，验证旧程序与数据库格式兼容
- 能力：能交付可运行服务，说明每种退出路径的承诺和回滚条件。
- 练习与预期结果：批次 A 已确认、B 提交后未确认时结束进程；重启后 A 完整存在，按同一键重试 B 仍只有一份；兼容版本回滚后查询结果一致。
- 项目或独立实验：交付 LogScan Linux 服务，提交停止、强制退出和版本回滚的命令与批次核对表。

#### TRK-10 交叉构建、链接布局与资源预算

- 先修：[CPP-01](cpp.md#cpp-01)、[ENG-04](engineering.md#eng-04)
- 层级：核心应用（方向选修）
- 状态：待编写。
- 问题：程序在宿主能跑，如何知道它能装进目标设备？
- 小节
  1. 选择目标架构、ABI、工具链和启动条件
  2. 检查 ELF 节、链接映射、闪存与 RAM 分配
  3. 区分静态量、栈预算、堆和运行期峰值
- 能力：能解释链接映射，定位大对象并用预算门槛拒绝超限版本。
- 练习与预期结果：以 STM32F407 Discovery 的 Cortex-M4 为示例目标，选 `arm-none-eabi-g++`，按目标的链接脚本记录 FLASH/RAM 各自的 ORIGIN、LENGTH 及 `.text`、`.data`、`.bss` 归属。先给项目设 4 KiB 的静态 RAM 练习预算；加入由入口实际读写的 8 KiB 数组，以 map/ELF 确认该符号进入 `.bss` 后，预算门槛应失败并标明区域。未接板时仅验收交叉编译与布局。
- 项目或独立实验：建立采集器的宿主和目标双构建，提交 map 文件、目标参数与预算表。

#### TRK-11 固定容量缓冲与字节流回放
