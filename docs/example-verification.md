## 2026-11-17：C++ 入门示例与 LogScan 基础实验

2026-11-17，本地 Windows x64。独立 C++ 示例用 MinGW-w64 GCC 13.1.0，以 `-std=c++20 -Wall -Wextra -Wpedantic -Werror` 构建；多文件工程用 CLion 随附的 CMake 4.2.2、Ninja 1.13.2 和同一个编译器，以 Debug 配置构建。构建产物和练习副本放在系统临时目录。

| 练习 | 实际验证 |
| --- | --- |
| 工具链 | 最小程序输出 `LogScan ready`；日志程序分开编译、链接后输出 `true`。改成短输入 `INFO` 得到 `false`。只声明、调用而未定义的函数能通过 `-c`，链接按预期失败。 |
| 分类器与生命周期 | 比较四行输入的标签和行数；`lifetime-int.cpp` 观察副本和引用，`lifetime.cpp` 观察追加、重分配、擦除；擦除变式末行为 `variant: 10 30 20`。 |
| RAII 与配套笔记 | 从正文提取文件清理跟踪程序并编译，核对正常结束、提前返回和异常传播的输出顺序。预览器测试了有内容与空文件；笔记的借用、复制以及前缀的有无空格变式与讲解一致。 |
| Git、CMake 与测试 | 独立练习仓库复现“暂存后再编辑”得到 `MM`。在 CMake 小工程里去掉库依赖，确认 `main.cpp.obj` 已生成而链接失败。将 LogScan 的缺文件诊断移到标准输出后，只让对应的 CLI 测试按预期失败；恢复后 CTest 全部通过。 |
| LogScan v0 | PowerShell 验收 8/8 通过，覆盖正常、空文件、坏行、末行无换行、CRLF 与其他 ASCII 空白、文件缺失、无参数和多余参数。 |
| LogScan v0.1 | 下载包的六个文件与源文件逐个比对了哈希。从干净目录构建，CTest 5/5 通过。同一组 8 个输入与错误场景下，v0 与 v0.1 的标准输出、标准错误和退出码一致。共享手算样本得到 `INFO 1`、`WARN 0`、`ERROR 1`、`UNKNOWN 1`。 |
| 站内验证 | `npm.cmd test` 4/4，`npm.cmd run build` 成功，Edge 浏览器测试 5/5。另检查了 11 页教程的折叠、375px 阅读宽度、正文里的站内链接和下载；验证章节下一篇顺序及生命周期旧续读锚点。 |

本次未在 MSVC、Linux/WSL 或 macOS 上重跑，也未在 CLion 图形界面逐步点击。未模拟文件成功打开后才出现的设备读取故障。涉及悬垂引用或视图的错误版本只做规则分析，不执行；一次正常输出不证明有未定义行为的代码是正确的。
