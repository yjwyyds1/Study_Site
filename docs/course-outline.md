# C++ 研习手册：课程总览

课程以 C++20 为基线，面向 Linux 上的通用 C++ 工程开发。初学可用 Windows PowerShell 与 MinGW，或直接在 Linux/WSL 开始。每次先预测结果，再运行、解释、修改和验证。一个 LogScan 项目贯穿各阶段。

**第一次打开本站，从[默认路线的第一天](curriculum/route.md#第一天)开始。** 安装工具、确定当前目录、构建第一个程序之后再进入 v0。遇到具体问题时用下表跳入学科，做完章节练习再回到[项目验收](curriculum/logscan.md)。

## 1 第一个 C++ 工具

先用构建和调试做诊断，再学习对象生命周期和资源管理。把知识用到第一个可复现的命令行工具。

**学习量参考：** 12–16 小时（示例约 1–2 周）。**阶段验收：** 在新构建目录跑通 LogScan v0；能区分配置、编译、链接和运行问题，解释一处借用何时失效，并复现正常、坏行和打开失败的结果。

### 1.1 工程入口：编译、链接与调试

**项目主线。先修：** 无。跑得出、读得懂错误、能定位失败，后续实验才有稳定反馈。

**模块验收：** 从空构建目录完成配置、构建和运行；分别复现一个编译错误和链接错误，并在断点处检查局部变量。

#### 1.1.1 从源码到可执行文件〔已发布〕

- 内容：用终端与 CLion 构建，区分编译、链接和运行失败，用断点检查变量。
- 编译：源码、头文件、编译标准与目标文件。
- 链接：声明、定义和常见未定义符号。
- 调试：预测输出，用 CLion 断点和单步观察变量。
- [阅读正文](../src/content/handbook/toolchain.md)

### 1.2 现代 C++：对象与资源

**项目主线。先修：** 工程入口：编译、链接与调试。能写出函数只是起点；清楚对象归谁、借多久，才能安全地组织接口。

**模块验收：** 画出一段代码的所有权与生命周期，修复一次悬空借用，并用标准 RAII 对象交付 LogScan v0。

#### 1.2.1 从空白写一个小程序〔已发布〕

- 内容：用分支、循环和函数完成日志分类；验证空输入与错误输入。
- 值：类型、变量、初始化与 const。
- 控制流：分支、循环、空输入和提前返回。
- 函数：拆分读取、分类与统计，明确参数和返回值。
- [阅读正文](../src/content/handbook/blank-program.md)

#### 1.2.2 作用域、存储期与对象生命周期〔已发布〕

- 内容：追踪局部对象、临时对象和容器元素的借用，修复失效的 string_view。
- 借用基础：作用域、对象生命周期、临时对象。
- 容器变动：区分 size 与 capacity，观察 vector 扩容。
- 练习：判断该保存值、下标还是短期借用。
- [阅读正文](../src/content/handbook/lifetime.md)

#### 1.2.3 RAII 与所有权〔已发布〕

- 内容：用文件流、unique_ptr 和锁守卫把资源释放绑定到作用域，包括提前返回和异常。
- 资源所有者：构造、析构、正常返回与异常。
- 独占所有权：用 unique_ptr 转移所有权，区分拥有和借用。
- 练习：用文件流管理打开与关闭，区分清理和读取成功。
- [阅读正文](../src/content/handbook/raii.md)

#### 1.2.4 实验：LogScan v0 单文件日志统计〔已发布〕

- 内容：按约定扫描日志并统计级别、坏行和退出码，提交可重跑的验收证据。
- 契约：参数、行格式、输出顺序与退出码。
- 实现：逐行读文件、判定首词、累计统计。
- 验收：正常、空文件、坏行、缺失文件和 CRLF。
- [阅读实验](../src/content/labs/logscan.md)

#### 1.2.5 值语义、复制与移动〔待编写〕

- 内容：用构造、赋值、拷贝省略和 Rule of Zero 分析 API 的值传递成本与行为。
- 区分对象构造和赋值；观察复制、移动与复制省略。
- 识别非拥有视图和移动前后的对象状态。
- 练习：优先用标准类型组合，判断何时需要自定义特殊成员。

#### 1.2.6 接口、错误与多态〔待编写〕

- 内容：比较值、引用与虚接口；用 optional、状态值和异常表示不同失败语义。
- 判断该按值、按引用还是按非拥有视图传参。
- 比较状态值、optional 和异常，标明如何区分失败类型。
- 练习：把错误处理从 CLI 输出中拆出来，再比较静态与运行时多态。

## 2 项目开发

先练 Git、CMake 多文件构建、自动测试和排错，再扩展 LogScan。常用标准库在项目中练，系统算法课程延后。

**学习量参考：** 36–48 小时（示例约 3–5 周）。**阶段验收：** 先交付 LogScan v0.1：拆分解析与命令行入口，跑通构建和回归测试。再交付 v1 多文件报告，验证汇总输出和错误处理。

### 2.1 工具链：CMake、Git 与 CI

**项目主线。先修：** 现代 C++：对象与资源。代码要能在另一台机器上被复现、审查、诊断并发布。

**模块验收：** 将 LogScan 拆成核心库和 CLI；用 Git 留下可审查的改动，在 CI 从干净检出完成构建并执行 CTest。

#### 2.1.1 命令行与版本控制入门〔已发布〕

- 内容：用工作目录和退出码复现问题；用 Git 留下一次可回看的改动。
- 终端：工作目录、参数、引号、标准输入输出与退出码。
- Git：工作区、暂存区、提交，读取 status、diff 和 log。
- 练习：保留一处小改动的输入、输出和差异。
- [阅读正文](../src/content/handbook/command-line-git.md)

#### 2.1.2 以目标为中心的 CMake〔已发布〕

- 内容：把解析库和命令行入口拆开，从干净构建目录构建、链接和运行。
- 配置、生成、构建、运行，定位每一步产生的文件。
- 以目标区分解析库、命令行入口和测试；设置头文件路径与 C++20。
- 练习：从空构建目录构建拆分版，故意漏链接再修复。
- [阅读正文](../src/content/handbook/cmake-targets.md)

#### 2.1.3 生成器、配置、依赖与产物〔待编写〕

- 内容：用 Presets 固定常用配置，区分单配置与多配置，记录依赖版本和构建产物。
- 区分源目录和构建目录、构建配置与不同生成器。
- 只追踪源文件和配置，明确依赖版本和生成产物。

#### 2.1.4 Git 评审与问题定位〔待编写〕

- 内容：用小提交、分支和 diff 提交评审；用 bisect 从一个可复现回归定位到变更。

#### 2.1.5 持续集成与构建矩阵〔待编写〕

- 内容：在 Linux 和 Windows 跑配置、构建及测试，记录失败日志和产物，区分缓存命中与构建正确。

### 2.2 质量：测试、诊断与可维护性

**项目主线。先修：** 工具链：CMake、Git 与 CI。让边界和回归有独立的验证方式，调试时才能缩小问题范围。

**模块验收：** 为真实缺陷保留一个能先失败的测试；用 ASan/UBSan 或等价工具解释诊断，再确认修复后的行为。

#### 2.2.1 自动测试与定位错误〔已发布〕

- 内容：验证解析函数和 CLI 行为；用失败用例缩小范围、修复并重跑。
- 单元测试：精确匹配级别，覆盖空行、前导空白和相似前缀。
- CLI 测试：比对 stdout、stderr 与退出码。
- 排错：让 `ERROR:` 的分类先失败，缩小到一个函数，修复后重跑。
- [阅读正文](../src/content/handbook/cli-testing.md)

#### 2.2.2 实验：LogScan v0.1 多文件工程〔已发布〕

- 内容：拆分解析库与命令行程序，用 CTest 锁住原行为并排查一次回归。
- 目标：分别构建解析库、命令行程序和测试。
- 验收：从干净目录构建，通过回归用例并保留一次失败到修复的记录。
- [阅读实验](../src/content/labs/logscan-build.md)

#### 2.2.3 最小复现与调试器〔待编写〕

- 内容：从失败输入缩小到一步，检查调用栈、观察点和变量，再用回归测试保留证据。
- 锁定可复现输入，记录期望与实际。
- 用断点、变量、调用栈验证假设；区分观察与推断。
- 练习：复现错误、定位一处条件判断、修复并重跑。

#### 2.2.4 告警、Sanitizer 与静态分析〔待编写〕

- 内容：为适用工具链建立独立检查配置；读懂一条诊断，记录误报和该工具未覆盖的路径。

#### 2.2.5 健壮性、属性测试与评审〔待编写〕

- 内容：用边界输入和参考实现检查性质；按失效场景审查所有权、输入边界、诊断与日志。

### 2.3 现代 C++：标准库与泛型接口

**项目主线。先修：** 现代 C++：对象与资源。掌握常用抽象与失效规则，能用标准库表达需求并控制接口的复杂度。

**模块验收：** 实现带类型约束的统计接口；用测试覆盖空输入、迭代器失效后的安全重取和结果顺序。

#### 2.3.1 容器、迭代器与失效规则〔待编写〕

- 顺序与稳定性：vector、deque、map、unordered_map。
- 操作成本：查找、追加、插入、擦除与重新分配。
- 练习：为多文件日志统计选容器，讲清顺序和边界。

#### 2.3.2 算法、lambda 与 ranges〔待编写〕

#### 2.3.3 模板、推导与 Concepts〔待编写〕

#### 2.3.4 标准库里的边界类型〔待编写〕

## 3 Linux 与项目交付

在 Linux 上交付可查询的日志归档，补齐系统调试和数据持久化，积累可用于简历、评审和面试的证据。

**学习量参考：** 48–64 小时（示例约 4–7 周）。**阶段验收：** 交付 LogScan v2：复现构建、导入和查询，演示失败回滚；用 README、测试、设计取舍和一份故障复盘支撑项目讲解。

### 3.1 操作系统与 Linux

**项目主线。先修：** 工具链：CMake、Git 与 CI。当程序在本机之外失效时，需要从进程、I/O 与操作系统边界拿证据。

**模块验收：** 用 shell、调试器和 strace 把一次 LogScan 失败定位到文件路径、权限、信号或 I/O 返回值，并复现修复。

#### 3.1.1 进程、线程与调度〔待编写〕

- 内容：理解用户态与内核态、进程地址空间、上下文切换、退出状态、信号和子进程回收。

#### 3.1.2 文件、描述符与 I/O〔待编写〕

- 内容：区分描述符、流、缓冲和页缓存；处理短读写、EOF、错误与描述符关闭责任。
- 区分路径、打开的文件和描述符。
- 观察读写返回值、部分读取、文件尾与失败。
- 练习：用诊断记录解释一次路径或 I/O 问题。

#### 3.1.3 虚拟内存、映射与分页〔待编写〕

- 内容：从虚拟地址到页表、缺页、写时复制及 mmap；比较映射与显式读取的约束。

#### 3.1.4 Linux 工程诊断〔待编写〕

- 内容：用 ps、/proc、strace、gdb 和 core dump 观察进程；保留命令、输入、假设和结论。

**项目主线。先修：** 现代 C++：标准库与泛型接口。源代码的操作次数不是全部成本；理解布局、访存和生成代码，才知道该测什么。

**模块验收：** 给出一份记录编译选项、数据规模、基线和重复测量的实验；把代表性汇编与一次布局或访存改动对应起来。

#### 3.2.1 位、数值与字节布局〔待编写〕

#### 3.2.2 内存层级与数据局部性〔待编写〕

- 内容：区分寄存器、缓存行、主存与 TLB；比较连续、跨步和随机访问。

#### 3.2.3 读汇编与调用约定〔待编写〕

- 内容：在 x86-64 或 AArch64 上对照源码、反汇编、寄存器、栈帧与参数传递；注明目标 ABI。

### 3.3 数据库与存储基础

**项目主线。先修：** 质量：测试、诊断与可维护性。让日志查询和归档有清楚的 schema、性能边界以及故障后的可预期行为。

**模块验收：** 在 SQLite 导入日志，用参数绑定查询时间和级别；对照索引前后查询计划，并证明一批失败不会留下部分提交。

#### 3.3.1 建模、SQL 与参数绑定〔待编写〕

#### 3.3.2 索引与查询计划〔待编写〕

#### 3.3.3 事务、锁和失败路径〔待编写〕

- 故意让中途一条失败，验收回滚后的记录数量和可见性。

#### 3.3.4 导入、迁移与备份恢复〔待编写〕

- 内容：对日志批次定义重复导入策略；在样本库上复现一次迁移、备份和恢复。

**模块验收：** 构建一个教学索引或表文件，验证崩溃后的记录边界并报告读写放大及空间开销。

## 项目链与方向产出

- **LogScan v0 · 单文件统计〔已发布〕：** 从命令行扫描一份日志，区分正常、坏行、用法错误与 I/O 失败；保留构建和命令输出。
- **LogScan v0.1 · 多文件工程〔已发布〕：** 将 v0 拆成解析库、CLI 和测试；从干净目录构建，复现、定位并修复一次回归。
- **LogScan v1 · 多文件报告〔待编写〕：** 复用解析器和样本，增加多文件聚合和固定顺序的报告；用自动测试与 CI 锁住原有行为。Top-K 可在算法补修中选做。
- **LogScan v2 · 可查询归档〔待编写〕：** 保留 CLI 报告，加入 SQLite 导入、查询和事务回滚，交付可被他人复现的项目记录。
- **LogScan v3 · 有界日志服务〔待编写〕：** 复用日志语义和数据库，加入有界接收、过载策略、恢复与关闭协议，建立性能基线。
- **LogScan · Linux 服务交付〔待编写〕：** 给服务加上运行指标、部署和回滚步骤，验证慢客户端和进程退出场景。
- **LogScan · 性能实验台〔待编写〕：** 对固定负载和环境发布可重跑的性能对比，保留正确性结果、原始数据和适用边界。
- **LogScan · 桌面查看器〔待编写〕：** 复用 v1 解析器，打包可取消、可筛选并能打开大文件的桌面应用。
- **LogScan · 资源受限采集器〔待编写〕：** 复用 v1 的记录语义和样本，在固定内存预算内采集、解析并回放字节流。

可选方向：Linux 服务端、基础设施与性能、Qt 与客户端、嵌入式 C++。什么时候选、每一批准备用什么验收，见[后续建设顺序](course-release-plan.md)。
