# C++ 长期课程：学习方法与里程碑

课程先建立共同的工程基础，再沿 LogScan 从命令行工具做到可部署的服务或方向作品。阶段完成的含义是能独立重做任务、解释取舍并出示证据，覆盖范围以实际完成的任务为准。

已有完整实验与参考的项目覆盖完整演进链：[v0 单文件工具](../src/content/labs/logscan.md)、[v0.1 多文件工程](../src/content/labs/logscan-build.md)、[v1 多文件聚合](../src/content/labs/logscan-v1.md)、[v2 SQLite 归档](../src/content/labs/logscan-v2.md)与[v3 有界 TCP 服务原型](../src/content/labs/logscan-service.md)。用[从零开始的默认路线](curriculum/route.md)学习，用[学科目录](course-outline.md)查阅。各项目的交付范围与验收夹具见[验收文档](curriculum/logscan.md)。

## 排期与验收

以 C++20 为教学基线；首批示例只用标准库。Windows 原生或 WSL/Linux 均可开课，进入 Linux 模块再单独验证 POSIX 行为。示例排期按每周 **10–14 小时专注学习** 换算，不设固定周量或截止日期。第一周记录实际能专注的时数、完成的产物和卡点，用实际节奏重算下一周。表中工时包含动手、调试、验收与复盘；两列周数取范围端点向上取整，分阶段各自估算。

| 阶段 | 工时 | 每周 10–14 小时 | 每周 6–8 小时参考 | 放行证据 |
| --- | ---: | ---: | ---: | --- |
| 起步 | 12–16 | 1–2 周 | 2–3 周 | 从新构建目录跑通 v0；能定位编译与链接问题，解释一处借用的边界。 |
| 项目开发 | 36–48 | 3–5 周 | 5–8 周 | v0.1 有多文件构建和测试；v1 进一步验证多文件汇总、错误和 CLI 契约。 |
| 近期求职 | 48–64 | 4–7 周 | 6–11 周 | 在 Linux 演示 v2 导入、查询和回滚，能用调试记录和机器层实验说明证据。 |
| 算法补修 | 按需 | — | — | 有基础则跳过；可选用 Top-K 或面试题检验。 |
| 长期基础 | 60–80 | 5–8 周 | 8–14 周 | v3 有分帧、背压、恢复、退出测试及可复跑的性能基线。 |
| 岗位方向 | 每条 48–72 | 4–8 周 | 6–12 周 | 交付一个方向作品和验收记录；按方向先修进入。 |
| 深水选修 | 每组 60–96 | 5–10 周 | 8–16 周 | 提交可证伪的假设、对照实验、原始数据与结论边界。 |

**第一周诊断（约 60–90 分钟）。** 先从终端或 IDE 的终端在新目录配置、构建和运行一份 C++20 程序；分别修复一个编译错误和链接错误，用断点记录一个局部变量；再展示一次 Git diff，解释一段代码的资源归属，并独立补一个坏输入用例。最后才用小题检查容器选择和复杂度。可以用既有作品替换题目，只要能从干净环境重跑、现场解释与复现。某项证据足够，就跳过对应讲解；有一项无法复现，就回补那一项，代码和验收仍要交。每次保留输入、命令、结果以及下一步，方便一周后调整。

**先修和节奏。** [课程数据](../src/data/curriculum.mjs)中，模块的 `requires` 是开课前应通过的模块验收；项目的 `requires` 列出项目中用到或一同验收的模块。阶段顺序用于默认排期，满足先修后可以并行，例如分别做算法与工程测试。下一次学习先复现上次结果，再做一个小改动，用失败用例或同伴评审检验。验收没过就用最小复现重做，已通过的章节可快进。客户端可在 v1 后分支，嵌入式还要完成机器层实验。

## 项目链与求职节奏

| 里程碑 | 复用与增量 | 交付 |
| --- | --- | --- |
| **v0 单文件统计 · 已发布** | 建立文本样本、级别统计、错误与退出码契约。 | 可重跑的 CLI 实验和退出码记录。 |
| **v0.1 多文件工程 · 已发布** | 在 v0 上拆分解析库、CLI 与 CTest；保持原有行为。 | 从干净目录构建，说明一次测试失败和修复。 |
| **v1 多文件报告 · 已发布** | 复用 v0.1 工程，增设多文件聚合和确定顺序的报告。 | 自动测试、CI 和整批输入失败处理。Top-K 是可选扩展。 |
| **v2 可查询归档 · 已发布** | 复用 v1 的解析和报告，增加 SQLite 批量导入、索引和参数化查询。 | Linux 构建说明、索引对照、事务回滚用例及故障复盘。 |
| **v3 有界日志服务 · 已发布** | 沿用 v2 的日志语义和持久化，增加 TCP 分帧、有界队列、超时、背压与有序关闭。 | 本机集成和恢复测试、固定负载的吞吐与尾延迟基线。 |
| **方向作品 · 计划** | Linux 服务端与基础设施/性能延伸 v3；Qt 查看器复用 v1 解析及报告；嵌入式采集器复用 v1 的样本与统计契约。 | 各选一个可运行产物，并展示方向特有的失败路径和约束。 |

近期求职优先跑通起步、共同基础和 v2 的交付验收，三个阶段合计约 **96–128 小时**，按示例投入约 7–13 周。可以从第一周挑几条目标岗位说明，分出必备能力、已有证据和待验证缺口。v1 可复现后开始模拟讲解或少量试投；v2 达到交付线后，可用每周 2–4 份针对性申请、一次模拟面试和一次回顾作为起点，再按反馈调整。简历只写自己完成并能复现的行为与结果，性能数字注明负载、环境与比较基线。长期沿 v3 选一条方向，从项目中的真实问题选深水专题。

**章节和建设顺序：** 见[完整分级大纲](course-outline.md)与[后续建设顺序](course-release-plan.md)。查资料时先看 [CMake 命令手册](https://cmake.org/cmake/help/latest/manual/cmake.1.html)、[Linux read(2)](https://man7.org/linux/man-pages/man2/read.2.html) 或 [SQLite WAL 文档](https://sqlite.org/wal.html) 等一手资料，再用固定版本和小实验检查自己的理解。
